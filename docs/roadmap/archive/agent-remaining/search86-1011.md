# search86-1011: search suggestions, history and undo in Settings (Brief 86, INBOX 832)

Branch `agent/search86-1011`, cut from `gemini/composer-improvements`. Decisions
a, b and c of Brief 86 are built; the owner's question was "should searches
suggest auto completions?? should the user be able to clear their cache and
recent searches in individual and all places and clear other things and undo
thing in settings??".

## Built

- (a) `frontend/js/search-suggest.js` (lazy): twelve boxes carry `data-search-scope`;
  recents, then note titles, tags and categories that start with the words, as
  rich picker rows, ghost text taken by Tab or Right, Escape closing the list
  before Find anything. One switch: Settings, General, Search. Recipe row in DESIGN.md.
- (b) Settings, Import & export, Clear and forget: recent searches everywhere,
  previews, the Guide's conversation, dismissed suggestions (server:
  `/suggestions/dismissed`, `/clear`, `/restore`; `learning.revive_dismissals`).
- (c) Recent changes (last twenty) and an Undo on the toast of every Settings
  change: `noteSettingChange` in status.js, `settingsHistory*` in settings-data.js.

## Two words in the brief that are not what the app has

- "The Guide's answer cache": the Guide stores no answers; its memory is the
  transcript in this window (`helpChatHistory`). The row clears that and says so.
- "Cached previews and thumbnails": no file on disk. The pictures, attachment
  facts and map previews are Maps in this window (`thumbUrlCache`,
  `attachmentMetaCache`, `referenceCountsCache`, `mapBoardIndexCache`, the API
  cache); the row clears them and says there is nothing to undo.

## Measured (Playwright, `scratchpad/ui-sweeps/searchsuggest86.js` and `settingsclear86.js`; light and dark, 1440 and 390)

- Ghost text sits 0.0 px from where the typed words end, in 24 of 24 states (independent span measure), after a fix: while the list is open the box's position is watched each frame, because a filter re-flowing the dock left the ghost 60 px right of the caret.
- Ghost text contrast 5.9:1 light and 8.3:1 dark (it was 4.2:1 light at 0.85 opacity, so the opacity went); `errors.js` 0 errors and 0 layout findings at 1440, 1024, 820 and 390.
- Escape: first closes the list, the second closes Find anything (list open false, dialog open true, then false).
- Clear recent, Shift+Delete on a lit recent, Undo from the toast: 3 recents to none to 3; 5 dismissed merges to 0 to 5; a switch changed and undone (server value restored); a look key set and removed again.
- Settings rows: no row spills at 1440 or 390; the Recent changes rows are 62 px (1440) and 84 to 106 px (390) with the button inside the row.
- App scripts together 320,589 of 320,600 gzipped (base 320,352): the eager half is the `apiJson` wrapper in status.js, the web panel's rows in chat.js and one listener in capture-ask.js; everything else is lazy (settings-data.js, search-suggest.js), and 14 redundant `typeof` guards on eager-file functions paid the difference. app.js 14,293 of 14,300.

## Left, one line each

- Suggestions in the Library's documents, boards, images, bookmarks, recordings and skills boxes are recents only; their own titles are not offered (the lists are lazy and have no shared title pool: `search-suggest.js` `searchSuggestWords` reads only `allEntries`).
- Find anything (`#finder-input`) shows the suggestion list over its own results while typing; measured fine at 1440 and 390, but a list over a list may want fewer rows there (`SEARCH_SUGGEST_LIMITS`).
- "Clear dismissed suggestions" does not reach a note's own "Not suggested" tags (`discarded_tags`, restored per note in the edit form): they are per-note, not a verdict list.
- Changes are recorded only while Settings is open (`settingsOpen()` in status.js's `apiJson` wrapper). A look setting is noticed from the `ui_state` copy a moment after it is written (about 1.5 s to its toast), and the top bar's theme button and a dashboard tint are not in Recent changes.
- Redo and Undo of a change in a pane that is not open redraw the open pane only (`showSettingsSection(currentSettingsSection)`); a control in another pane reads the new value when it opens.
- Undo of a Guide clear restores the words, not the badges and sources under an answer (`restoreGuideTurns`, settings-data.js).
- Every scope keeps eight recents (`SEARCH_RECENT_MAX`, search-suggest.js); the store is lazy, and chat.js still writes the web panel's list under its old key, so the panel needs nothing lazy to show it.
- Not verified: a screen reader reading the list (the roles and the polite count are in, the speech is not heard); a touch device (the sweep is a 390px desktop context, `hasTouch` not set); Windows and macOS desktop shells.
- Found, not fixed: app.js sits 7 gzipped bytes under its cap (14,293 of 14,300) after trimming six redundant `typeof` guards in the log hook; the next addition there needs a cut or a move first.
