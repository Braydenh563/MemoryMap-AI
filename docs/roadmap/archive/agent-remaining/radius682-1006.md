# radius682-1006: controls inside rounded containers (INBOX 682, 683)

Worktree `agent-ae9d09b09c4f00a68`, merged from `claude/mini-release-0.4.1`.
The owner: "should these have rounded edges to stay consistent??" (the
Documents sidebar tabs) and "the square active goes out of the circular pill"
(the table bar's "Copy | ... | X").

## Landed

- 682 root cause: `#doc-sidebar-tabs` carried `.seg` as well as `.tabs-line`, so
  the flat looks' choice-control fill, 1px control edge and 0 corner (the
  `:is(.seg, #tab-bar)` glide defaults, 08-consistency.css) drew the chosen tab as
  a grey bordered slab. The class is removed (no other strip had it), the two
  `:not(.doc-sidebar-tabs)` exemptions it needed are gone, and every
  `.tabs-line > button` takes `--radius-md` on all four corners.
- 683: the bar is the table's `.code-actions` (markdown.js, navigation.js).
  Its buttons used `--radius-inner`, a card surface's concentric corner that is
  0 below a 12px corner setting.
- Tokens (`00-tokens-shell.css`): `--radius-in-pill`, `--radius-in-choice`,
  `--radius-in-md`. DESIGN.md "Controls inside a rounded container" holds the
  table; `tests/test_ui_recipes.py` (`CONTROLS_IN_ROUNDED_CONTAINERS`, the token
  definitions, no element both `.seg` and `.tabs-line`) holds the set.
- Sweep: `scratchpad/ui-sweeps/radius682.js` (container and child corner at
  rest, hover and keyboard focus; light and dark, 1440 and 390, Classic and
  Quiet utilitarian): 681 of 681 pass after, the base fails 6 surfaces.

  a pill). The chat dock's controls, the board's context bar, the stepper and
