### How links get their reasons

- `manager.create_link` -> `_deduce_reason`: a cosine of 0.55 or more gives
  the literal `AUTO_REASON_TEXT` ("similar in meaning", or "..., and around
  the same time" for a date rescue) with the score in `reason_confidence`.
  Every caller without words of its own lands here: the wiki `[[name]]`
  links (`origin="wiki"`, which then read "similar in meaning" although one
  note names the other), the AI's link tool, the graph and the Notes link
  button.
- `ai/relations.recognise` (KG2) already names specific evidence for
  *suggestions*: shared entities, shared neighbours, rare shared tags. An
  accepted suggestion keeps its sentence. Nothing applied it to links that
  exist.
- `POST /entries/links/backfill-reasons` (job `link-reasons`): fills empty
  reasons with the generic text, then asks the model (`ai/links.audit_vague_links`)
  to reword them. Without a model the result is more "similar in meaning".
  Its only button is "Explain your existing links" inside the suggestions
  inbox's Links pane.

### How tags arrive

- Tags are the person's: filing never applies a tag. It keeps up to five
  `suggested_tags` (the model's, else `lexical_filing.suggest_tags`) for the
  person to take or discard (INBOX 440). There is no per-tag confidence.
- Tags another actor wrote: the agent's tag tools (`ai:<tool>` in the audit
  log), the autonomous pass's `stale` tag (`auto_stale_review_enabled`),
  passive capture's tag. The audit log's `actor` is the only provenance.

### The three hidden features fixed in this work

1. **Find duplicates** (Settings only) becomes a Tidy review (near-duplicate
   notes) and a Tools & features row.
2. **Explain existing links** (inside the suggestions inbox) becomes Tidy's
   "Give links specific reasons" run, with no model needed, and a Tools &
   features row.
3. **Manage tags / `is:review`** (a kebab item and a typed filter) get Tools
   & features rows, and Tidy's tag and category reviews open them.

Each is reachable within two clicks from the Notes dock: Tidy (one click),
then the review's select (two).
