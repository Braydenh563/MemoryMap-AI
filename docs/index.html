Quick Start

Get MemoryMap AI running locally in under five minutes. You'll need Python 3.11+, Ollama, and a model pulled locally.

Prerequisites

  • Python 3.11+ — check with python --version
  • Ollama — install from ollama.com
  • A local model — recommended: ollama pull llama3.2
  • An embedding model — ollama pull nomic-embed-text

Installation

  1. Clone the repository 
    git clone https://github.com/Braydenh563/MemoryMap-AI.git
cd MemoryMap-AI
  2. Install Python dependencies 
    pip install -e .
  3. Configure your models

    Copy config.example.json to config.json and set your preferred Ollama model and embedding model.

    {
  "model": "llama3.2",
  "embed_model": "nomic-embed-text",
  "ollama_url": "http://localhost:11434"
}
  4. Start the backend 
    python -m memorymap_ai.server
  5. Open the UI

    Navigate to http://localhost:7532 — the glassmorphism interface loads instantly.

💡 On first launch MemoryMap AI creates a local SQLite database and initialises the ChromaDB vector store in ~/.memorymap/. No additional setup required.

Architecture

MemoryMap AI is a single-process Python server with a pure HTML/CSS/JS frontend. There are no external services, no authentication tokens, and no network calls outside your machine.

Frontend

Vanilla HTML + CSS + JS. Glassmorphism UI, tab-based navigation, live streaming via SSE.

Backend

Python (FastAPI). REST + SSE endpoints. Handles memory CRUD, AI orchestration, reminders.

Vector store

ChromaDB (local). Embeds and indexes every note for semantic retrieval.

Relational store

SQLite via SQLAlchemy. Notes, reminders, activity log, conversation history.

Inference

Ollama (local). Swappable model. Supports tool calling for structured memory operations.

Embeddings

nomic-embed-text (or any Ollama embed model). Runs entirely on device.

Data flow

When you save a note the backend writes it to SQLite, embeds it via Ollama, and upserts the vector into ChromaDB. When you ask a question the query is embedded, the top-k most similar notes are retrieved, and those are injected into the LLM prompt as grounding context. The streamed response is sent back over SSE.

User input
  → FastAPI /ask endpoint
  → embed query  (Ollama nomic-embed-text)
  → vector search (ChromaDB top-k)
  → build prompt  (system + retrieved notes + user query)
  → stream tokens (Ollama LLM)
  → SSE → frontend

Configuration

All settings live in config.json at the project root. You can also change most of them live from the Settings → Appearance and Settings → AI panels in the UI.

Key options

  • model — Ollama model tag for chat inference (e.g. llama3.2, mistral)
  • embed_model — Ollama model tag for embeddings (e.g. nomic-embed-text)
  • ollama_url — Base URL for your Ollama instance (default http://localhost:11434)
  • top_k — Number of notes retrieved per query (default 6)
  • port — Server port (default 7532)
  • data_dir — Where SQLite and ChromaDB are stored (default ~/.memorymap/)

🔄 Changing embed_model after you've stored notes requires re-embedding the entire collection. Use the Settings → AI → Re-embed all button in the UI.

Switching models

Any model available via ollama list can be used. Models with native tool calling (Llama 3, Mistral, Qwen 2.5) give the best structured memory operations. You can also use GGUF quantised models for lower VRAM — just ollama pull the variant you want.

Roadmap active

MemoryMap AI is under active development. The full roadmap lives in docs/ROADMAP.md. Key upcoming areas:

  • Agent skills — pluggable tools the AI can invoke (web search, calculator, calendar sync)
  • Graph view — visualise note links as an interactive memory map
  • Mobile PWA — installable on iOS/Android, syncs over local network
  • Multi-user — per-user isolation with optional shared spaces
  • Export / import — Markdown vault, Obsidian-compatible format
  • QAT model support — optimised quantisation-aware inference paths
